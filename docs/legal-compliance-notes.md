# 法令・規約メモ

- 更新日: 2026-03-30
- 目的: 実装時に見落としやすい日本法と利用規約上の論点を、開発メモとして残す
- 注意: これは法的助言ではない。実運用前、とくに `real`、`SELL_SHORT`、第三者向け提供、VPS 常駐化の前には一次情報と専門家確認を行う

## 現時点の前提

- この repo は自己口座・自己資金での利用を前提とする
- 同梱戦略は `noop` のみで、売買助言サービスや第三者運用サービスとしては扱わない
- `OpenD + ローカル PC` を前提とし、コロケーションや専有サーバ前提の高速化はまだ行わない

## 実装時に必ず意識すること

- 他人資金を運用する実装を入れない
- 他人の口座へ自動発注する機能を入れない
- 有償・継続的な売買シグナル配信機能を入れない
- 約定意思のない注文を前提にしたロジックを入れない
- 価格形成を人為的にゆがめる前提のロジックを入れない
- API や市場データの再配信機能を入れない

## とくに危ない論点

### 不公正取引

- 見せ玉、仮装売買、馴合売買、終値関与、買い上がり・売り崩しのような相場操縦的ロジックは禁止対象になり得る
- 注文自動取消は直ちに違法ではないが、約定意思のない板出しを前提にすると危険
- 実装上は「約定意思のある注文だけ出す」を原則にする

### 空売り

- `SELL_SHORT` を JP 市場で実運用する前に、空売り価格規制、明示・確認義務、残高報告義務の要否を再確認する
- 現状コードでは JPX の空売り価格規制トリガー判定や大量空売り報告の管理までは実装していない
- そのため、JP 市場の `SELL_SHORT` は「技術的に API を呼べること」と「法令順守できていること」を同一視しない

### 高速取引行為

- 金融庁は株式等の高速取引行為について登録制を案内している
- 現在の `ローカル PC + OpenD` は典型的な専有インフラ型とは少し距離があるが、VPS 常駐、専有サーバ、低遅延化、実質的な高頻度化へ進むなら再確認する
- インフラを変えるときは、この論点を必ず設計レビュー項目に入れる

### 業登録

- 自己売買の範囲を超えて、第三者資金運用、売買一任、継続的な有償助言へ進む場合は、投資運用業や投資助言・代理業の論点が出る
- その方向の要件は、この repo の対象外とする

### moomoo の利用規約

- API や市場データの第三者提供、再配信、過度な負荷、規約外利用は避ける
- 規約上の制限は法令とは別のリスクなので、機能追加時に毎回確認する

## 実装ガードの方針

- `real` を有効にする変更では、法令・規約影響を PR 説明または作業メモに明記する
- JP 市場で `SELL_SHORT` を既定有効にしない
- 板寄せ直前・大引け直前の特殊な価格形成へ関与しやすい戦略は、明示レビューなしで追加しない
- 大量注文や高頻度取消を行う戦略は、まず `simulate` と手動レビューで止める
- 第三者利用や配信を想定したインターフェースは、要件確定前に追加しない

## 再確認が必要な変更

- `SELL_SHORT` / `BUY_BACK` を JP 市場で本番有効化する変更
- `real` での常駐自動売買を前提にする変更
- VPS、クラウド、専有サーバ、低遅延ネットワークへ移す変更
- 複数ユーザー対応、マルチアカウント対応、外部向けシグナル配信を追加する変更
- 市場データの保存・再配信・外部公開を追加する変更
